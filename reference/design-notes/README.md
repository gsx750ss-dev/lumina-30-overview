# LUMINA-30 Design Notes
# LUMINA-30 設計メモ

Status: supplementary design-note archive / 補助設計メモ・アーカイブ
Scope: non-canonical explanatory notes; not a front-door guidance page, certification material, compliance standard, or operational checklist

This folder preserves non-canonical design notes that help maintainers and advanced readers understand supporting ideas, limits, objections, and possible uses around LUMINA-30. Files here are not LUMINA-30 canonical definitions, not public guidance, not certification documents, not compliance standards, and not evidence of institutional adoption.

このフォルダは、LUMINA-30に関する補助的な考え方、限界、異議、利用可能性を、保守担当者や高度な読者が確認できるように保存する非正典の設計メモ・アーカイブです。ここにある文書は、LUMINA-30の正典定義、公開ガイダンス、認証文書、準拠標準、組織的採用実績ではありません。

## Purpose

Use this folder to keep supporting notes without promoting them into the main reader path. A note may explain why a concept was recorded, where it may be useful, where it may be misread, and how it relates to the fixed LUMINA-30 core.

このフォルダは、補助メモを主要読者導線へ前面化せずに保持するために使います。各メモは、概念を記録した理由、利用可能性、誤読リスク、固定されたLUMINA-30中核との関係を説明するものです。

## What belongs here

A note may belong here if it:

- preserves a useful LUMINA-30 design observation that should remain available for later review;
- records a supporting concept without changing the canonical core;
- explains usefulness, limits, objections, and possible misreadings;
- remains separate from primary public pages, operational checklists, FAQ entries, and normative rules.

このフォルダに置いてよい文書は、次の条件を満たすものです。

- 後から確認できるように、有用なLUMINA-30設計上の観察を保存する
- 正典的中核を変更せず、補助概念を記録する
- 有用性、限界、異議、誤読可能性を説明する
- 主要公開ページ、運用チェックリスト、FAQ項目、規範的ルールとは分けて扱う

## What does not belong here

Do not use this folder for:

- canonical LUMINA-30 text;
- certification claims;
- claims of legal, regulatory, academic, institutional, or external adoption;
- raw chat dumps without purpose, objections, limits, and relationship to the fixed core;
- files that modify existing public navigation without review.

このフォルダには、次のものを置きません。

- LUMINA-30の正典本文
- 認証主張
- 法的・規制上・学術上・制度上・外部採用の主張
- 目的、異議、限界、固定中核との関係を持たない生の会話ログ
- レビューなしで既存公開導線を変更するファイル

## Required structure for new notes

Each new note should include, at minimum:

1. status and scope;
2. why the note exists;
3. intended uses;
4. likely objections and limits;
5. relationship to the fixed LUMINA-30 core.

新しいメモには、最低限、次を含めます。

1. ステータスと対象範囲
2. 文書が存在する理由
3. 想定される使い道
4. 想定される異議と限界
5. 固定されたLUMINA-30中核との関係

## Default reader rule

The default status of this folder is supplementary archive. Files here should not be treated as the main entry point for readers. When a concept is needed for public use, it should be reviewed and expressed separately in the appropriate public guidance, FAQ, operational material, or index page.

このフォルダの既定ステータスは補助アーカイブです。ここに置かれたファイルは、読者の主要入口として扱いません。公開利用に必要な概念は、別途レビューし、適切な公開ガイダンス、FAQ、運用資料、索引ページの中で表現します。

## Naming convention

Use lower-case kebab-case filenames. Prefer descriptive names that state the concept and the purpose of the note.

ファイル名は小文字のケバブケースを使います。概念名と文書目的が分かる説明的な名前を優先します。

Example pattern:

concept-name-purpose-note.md

例：

concept-name-purpose-note.md
