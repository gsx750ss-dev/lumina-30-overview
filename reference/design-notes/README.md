# LUMINA-30 Design Notes
# LUMINA-30 設計メモ

Status: repository preservation area / リポジトリ内保存領域
Scope: non-canonical design notes and future integration candidates

This folder is for standalone design notes that preserve high-value LUMINA-30 discussions before they are integrated into public guidance, FAQ, review floors, operational templates, or canonical materials.

このフォルダは、LUMINA-30に関する高価値の議論成果を、公開ガイダンス、FAQ、レビューフロア、運用テンプレート、または正典資料へ統合する前に保存するための単体設計メモ置き場である。

## Purpose

Use this folder when a discussion produces a useful concept, warning, limitation, or future integration candidate, but the material should not yet be promoted into the main public navigation.

このフォルダは、議論から有用な概念、警告、限界、将来統合候補が生まれたが、まだ主要公開導線へ出すべきではない場合に使う。

## What belongs here

A note may belong here if it:

- preserves a high-value LUMINA-30 discussion that may otherwise be lost in chat threads;
- records a future integration candidate without changing the canonical core;
- explains why a concept is useful, where it may be misread, and when it should or should not be publicized;
- is not yet ready to become a primary public page, operational checklist, FAQ entry, or normative rule.

このフォルダに置いてよい文書は、次の条件を満たすものとする。

- チャットスレッド内で失われやすい高価値のLUMINA-30議論を保存する
- 正典的中核を変更せず、将来統合候補を記録する
- 概念の有用性、誤読リスク、公開すべき時期と公開すべきでない時期を説明する
- まだ主要公開ページ、運用チェックリスト、FAQ項目、規範的ルールにする段階ではない

## What does not belong here

Do not use this folder for:

- canonical LUMINA-30 text;
- certification claims;
- claims of legal, regulatory, academic, institutional, or external adoption;
- raw chat dumps without purpose, objections, limits, and integration timing;
- files that modify existing public navigation without review.

このフォルダには、次のものを置かない。

- LUMINA-30の正典本文
- 認証主張
- 法的・規制上・学術上・制度上・外部採用の主張
- 目的、異議、限界、統合タイミングを持たない生の会話ログ
- レビューなしで既存公開導線を変更するファイル

## Required structure for new notes

Each new note should include, at minimum:

1. status and scope;
2. why the note exists;
3. intended uses;
4. likely objections and limits;
5. publication or integration timing;
6. relationship to the fixed LUMINA-30 core.

新しいメモには、最低限、次を含める。

1. ステータスと対象範囲
2. 文書が存在する理由
3. 想定される使い道
4. 想定される異議と限界
5. 公開または統合タイミング
6. 固定されたLUMINA-30中核との関係

## Default publication rule

The default status of this folder is preservation-only. Files here should remain unlinked or only lightly referenced until a later review decides that they should be integrated into public guidance, FAQ, operational material, or another visible entry point.

このフォルダの既定ステータスは保存専用である。ここに置かれたファイルは、後続レビューで公開ガイダンス、FAQ、運用資料、または可視導線へ統合すべきと判断されるまで、リンク無し、または弱い参照に留める。

## Naming convention

Use lower-case kebab-case filenames. Prefer descriptive names that state the concept and the purpose of the note.

ファイル名は小文字のケバブケースを使う。概念名と文書目的が分かる説明的な名前を優先する。

Example pattern:

concept-name-purpose-note.md

例：

concept-name-purpose-note.md
