# L30 可逆復帰実装チェックリスト

## このチェックリストの使い方

境界上の懸念、インシデントレビュー、一時停止、停止条件が確認された後に使用します。各チェック項目は、単なる主張ではなく証拠に基づいて確認されるべきです。

**推奨記録：**各セクションについて、`証拠`、`不足`、`対応`、`責任者`、`再進行状態`を記録します。

## 実務利用手順

レビューで、境界懸念の特定、証拠保全、このチェックリストの利用、マトリクスによる役割割り当て、再進行状態の判断、長期監視の順番を整理したい場合は、[実務利用手順](./JP_L30_RETURN_TO_REVERSIBILITY_PRACTICAL_USE_SEQUENCE.md)を使います。

## 役割・証拠マトリクス

レビューで、誰が停止を維持し、誰が証拠を保全し、誰が実効的拒否を回復し、誰が再進行をレビューするのか、またそれらの役割が名目ではなく実効的であることを示す証拠を確認する必要がある場合は、[可逆復帰 役割・証拠マトリクス](./JP_L30_RETURN_TO_REVERSIBILITY_ROLE_EVIDENCE_MATRIX.md)を使用します。

## 1. 停止条件と対象範囲

- 停止または一時停止の条件が記録され、継続運用が実効的拒否、証拠、修正、可逆性を弱める理由が説明されている。
- 対象となるシステム、導入、業務、判断経路の範囲が明確である。
- レビュー中に追加の不可逆的エスカレーションを許していない。
- 停止を維持する権限が特定され、迅速な再進行から利益を得る同じ主体だけで迂回できない。

## 2. 証拠保全

- 判断記録、警告、承認、拒否試行、上書き、ログ、介入可能時間が保全されている。
- 証拠欠落は不足事項として記録され、実効的拒否が存在した証明として扱われていない。
- 証拠保全の責任は、迅速な再進行の誘因だけに依存しない役割へ割り当てられている。
- 保全された記録を、再進行に疑義を出せる人または組織が確認できる。

## 3. 実効的拒否の回復

- 人間の拒否権保持者が特定されている。
- 拒否が、不可逆的影響の前に、関連する進路を延期・拒否・上書き・方向修正・停止できる。
- 人間判断に、結果へ影響するための時間、情報、権限がある。
- プロセスが、実際の拒否と見せかけの拒否を区別できる。

## 4. 境界診断と是正制御

- 境界失敗または境界失敗に近い状態が、実務上の言葉で記述されている。
- 是正制御が、拒否、証拠、修正、ロールバック、監視を弱めた仕組みに対応している。
- 問題を生んだ同じ不可逆的エスカレーション経路へ戻っていない。
- 是正内容は、再進行を検討する前に、試験可能・レビュー可能・文書化済みである。

## 5. 制御された再進行のみ

- 再進行の範囲、期間、依存、影響経路が限定されている。
- 再進行開始前に、ロールバック条件または再停止条件が定義されている。
- 再進行期間の監視担当が割り当てられ、形式的監視として扱われていない。
- 制御された再進行を、認証、承認、法令適合、または停止前進路の全面再開として説明していない。

## 6. 敵対的形骸化への耐性

- 再進行判断が、速度、証拠の最小化、不可逆的エスカレーションから利益を得る主体だけに依存していない。
- 証拠欠落は未解決のレビュー条件として扱われ、問題なしの根拠にされていない。
- レビューが儀式化していないか確認され、なお停止・拒否・方向修正が可能である。
- 見せかけの拒否、見せかけの可逆性、見せかけのレビューを、実効的拒否、可逆性、手続的有効性として扱っていない。

## 7. 長期継続性

- 停止権限、証拠保全、境界レビュー、再進行レビューの役割が、引き継ぎ可能な形で定義されている。
- 証拠保全期間と定期境界レビューが、当該インシデント直後だけでなく継続的に設定されている。
- システム、制度、技術が変化したとき、停止条件と再停止条件が更新される。
- 停止・検証・拒否・修正・復帰の能力が、組織変更を越えて生きたまま維持される。

## レビュー結果

| 結果 | 使用する条件 |
| --- | --- |
| 再進行しない | 実効的拒否、証拠、是正制御、再停止条件が欠けている、または検証不能である。 |
| 限定的な制御された再進行のみ | 最低条件はレビュー可能だが、監視、範囲限定、ロールバック条件がなお必要である。 |
| 監視を継続する | 再進行は始まっているが、長期可逆性、証拠保全、形骸化防止チェックを維持する必要がある。 |

**境界ルール：**実際の拒否と見せかけの拒否を区別できない場合、そのプロセスは可逆性へ復帰していない。
